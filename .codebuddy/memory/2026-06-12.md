## LLM 巨慢问题 — 正确根因与修复

**症状**：`qwen3.5:0.8b` 单请求 60s 超时，所有 token 进入 `thinking` 字段，`response` 始终为空。

**根因**：`qwen3.5:0.8b` 模型在 2026-06-11 被更新，新增 `"thinking"` capability。Ollama 官方 API 使用顶级参数 `"think": false` 关闭推理阶段，而非 `options` 里的字段（之前试了 `options.enable_thinking` 无效就是因为放错了层级）。

**关键发现**：`"think": false` 是 `/api/generate` 和 `/api/chat` 的顶级参数，文档明确说明 "should the model think before responding?"。

**测试验证**：
- `qwen3.5:0.8b` + `"think": false` + 分类 prompt：848ms，17 tokens，`response: "category: src directory; purpose: Keep project structure..."`，自然停止
- 无论 num_predict=50/200/500/2000，不加 `think:false` 则 response 始终为空

**最终修复**：
1. `GenerateRequest` 加 `think: bool` 字段，`#[serde(skip_serializing_if = "std::ops::Not::not")]`，始终序列化为 `false`
2. 保留 `qwen3.5:0.8b` 默认模型
3. 保留原始 system prompt（含 rules）
4. `num_predict=300` 安全上限（带 `think:false` 模型 ~20 tokens 自然停止）

## 遵循官方 API 重构 llm.rs

按照 Ollama 官方 API 规范重构 `src/enrich/llm.rs`：

**删除的旧代码**：
- `strip_think()` 函数（28 行） — `think: false` 后模型不产出 think blocks
- `extract_category_purpose()` 函数（28 行） — 改用 JSON Schema 约束输出
- `parse_summary()` 中的第 3/4 步降级解析（文本回退逻辑）
- System prompt 拼接为 prompt 的模式：`"System: ...\n\nUser: ...\n\nReply:"`

**新增/改进**：
1. **`system` 字段** — `GenerateRequest` 新增 `system: Option<String>`，作为 `/api/generate` 顶层参数，不再拼接到 prompt 字符串
2. **分类任务用 JSON Schema** — `format` 传 `{"type":"object","properties":{"category":...,"purpose":...},"required":[...]}`，模型直接输出合法 JSON，无需文本解析
3. **`preload_model()`** — 发送 `{"model":"..."}`（无 prompt）预热模型到 GPU 内存，避免首次请求冷启动
4. **`prompt: Option<String>`** — prompt 字段改为可选，preload 时不传 prompt
5. **`GenerateResponse` 补全** — 添加 `thinking`、`done`、`done_reason` 字段

**mod.rs 集成**：`enrich_items()` 启动时调用 `preload_model()`，模型就绪后才启动 supervisor + worker

## 迁移至 ollama-rs 社区库

用 `ollama-rs` (pepperoni21, 1000⭐, 347k downloads) 替换手写的 reqwest Ollama 客户端。

**Cargo.toml 变更**：
- 新增 `ollama-rs = "0.3"`、`tokio = { features = ["rt-multi-thread", "time"] }`、`schemars = "1"`
- 保留 `reqwest`（content.rs 的 HTTP 内容过滤仍需要）

**llm.rs 重写要点**：
- 删除手写的 `GenerateRequest`/`GenerateOptions`/`GenerateResponse` 等结构体（~90 行）
- 删除 `send_generate()`/`chat()`/`chat_with_schema()` 底层 HTTP 函数（~60 行）
- 使用 `ollama_rs::Ollama` + `GenerationRequest` builder API
- `format` 用 `FormatType::StructuredJson(Box::new(JsonStructure::new::<Schema>()))` — 通过 `#[derive(JsonSchema)]` 自动生成 JSON Schema，替代手写 JSON 常量
- `keep_alive` 用 `KeepAlive::Until { time: 10, unit: TimeUnit::Minutes }`
- `think(false)` 保持推理关闭
- `ModelOptions::default().temperature(0.1_f32).num_predict(300)`（ollama-rs 用 f32/i32）
- `health_check` → `ollama.list_local_models()`
- `preload_model` → 发送最小 prompt "." + keep_alive 预热
- `summarize_report` 用 `tokio::time::timeout` 包装超时
- 全局 `OnceLock<tokio::runtime::Runtime>` 提供 `block_on` 能力

**mod.rs 变更**：
- 删除 `reqwest::blocking::Client` 创建和传递（不再需要 HTTP 连接池）
- `do_summarize()` 签名从 `(&Client, &str, &str, ...)` 简化为 `(&str, &str, ...)`
- `summarize_report()` 调用不再传 client 参数
- `spawn_workers()` 闭包移除 `client: Arc<reqwest::blocking::Client>` 参数
