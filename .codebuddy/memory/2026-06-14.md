## OLLAMA_NUM_PARALLEL 配置
- `OLLAMA_NUM_PARALLEL` 是 Ollama 服务启动参数，运行时无法通过 API 修改，必须在启动前注入
- 修改 `scripts/setup_ollama.ps1`，新增 `-NumParallel` 参数（默认 4），在三个位置注入：
  1. `$env:OLLAMA_NUM_PARALLEL` — 当前进程
  2. `[Environment]::SetEnvironmentVariable(..., "User")` — 持久化用户级
  3. `$psi.EnvironmentVariables[...]` — 两个子进程（ollama list 触发服务 + ollama serve 回退）
- 注意：`ollama list` 触发的是 Windows 服务，服务可能不继承脚本子进程的环境变量——此时靠持久化的 `[Environment]::SetEnvironmentVariable` + 重启 Ollama 生效

## setup_ollama 卡住问题修复
- **根因**: `tee_run.ps1` 旧版用 `*>` 重定向到临时文件，脚本跑完才显示输出。且 PS 5.1 中 `Write-Host` 不走任何流，`*>` 根本无法捕获——日志和画面都为空
- **修复**: 将 `tee_run.ps1` 改为使用 `Start-Transcript`（PS 5.1 原生支持），它会 hook 进 host 层面，能正确捕获 `Write-Host`
- **验证**: 系统已安装 aria2 (`%LOCALAPPDATA%\aria2\aria2c.exe`) 和 Ollama (`%LOCALAPPDATA%\Programs\Ollama\ollama.exe`)，脚本检测逻辑正确，无需重复下载

## OLLAMA_NUM_PARALLEL 全矩阵测试 → 吞吐量导向重构

### 测试发现
- 用 qwen3:0.6b 测试了 N={1,4,16,64} × C={1,2,4,8,16,32,64,128} 完整矩阵
- **OLLAMA_NUM_PARALLEL 对小模型完全无效**：N=1/4/16 的 EffPar 几乎相同（C=32 时 N=1→25.32, N=4→25.97, N=16→25.48）
- N=64 直接挂了（iGPU 显存不足预分配 64 个 slot）
- GPU 确认：RTX 4060 Laptop GPU 8188 MiB，Ollama 走 CUDA
- `OLLAMA_IGPU_ENABLE` 对 NVIDIA 无效，可以删掉

### 吞吐量最优并发
- C=32 吞吐量最高（17.1 req/s），C=8 只有 5.9 req/s（差 3x）
- Vegas 以延迟为目标收敛到 cwnd=7~8，吞吐量是次优的

## CWND_INIT → cwnd_init() 运行时函数

- **变更**: `pub const CWND_INIT: usize = 8` → `pub fn cwnd_init() -> usize { worker_thread_limit(usize::MAX) }`
- **原因**: GPU 不会饱和（瓶颈在 CPU 调度），cwnd 可以直接从最优值开始，无需 ramp-up
- **效果**: 启动时 cwnd = 2× logical processors（当前机器 16→32），直接达到峰值吞吐量
- **文件**:
  - `src/consts.rs`: 常量→函数，移除相关 const 断言（`CWND_INIT >= CWND_MIN`, `MAX_SAFETY_CWND > CWND_INIT` 等）
  - `src/enrich/mod.rs`: `CwndCtl::new()` 调用 `cwnd_init()`，日志行用 `cwnd_init()`，`CWND_MIN` 移入测试模块局部 import
  - 全部 71 个测试通过，零 warning
