# disk_organizer — 功能文档（Functional Spec）

> 版本：2026-06-08 · 状态：设计稿待评审

## 1. 背景与目标

C 盘（NTFS）随使用不断膨胀，但现有工具（WizTree/WinDirStat）只回答"**哪里大**"，不回答"**这是什么、能不能删**"。本工具的目标：

> 扫出磁盘里占地最大的**节点**（大文件 **和** 大目录），为每个节点附上**用途解释**与**清理风险**，由**用户自己勾选**要删的东西。

定位：一个**做着玩、用来探索技术组合**的项目——核心价值在于把"高性能并行扫描 + 规则库 + 多个本地小模型（文本/视觉）"拼到一起，而非做一个商业产品。

## 2. 核心原则（不可妥协）

1. **程序绝不自动删除。** 工具只产出"带解释的清单 + 风险标注"，**删除与否 100% 由用户决定**。
2. **性能优先。** 全盘遍历必须多核并行，先把"大小地图"秒级呈现。
3. **渐进增强。** 结果分阶段刷新：先有大小与规则标签，文本 LLM 解释随后流式补上，视频分析最后延后触发。用户全程不必干等。
4. **解释要可信。** 风险等级来自**确定性规则**，绝不让 LLM 拍板"可安全删除"；LLM 只负责"猜用途/做体检/总结"。

## 3. 使用场景（User Stories）

- **诊断膨胀**：我想知道 C 盘 80GB 到底被什么吃了——不只是"哪个文件大"，而是"哪类东西大、是不是垃圾"。
- **识别开发垃圾**：npm-cache / .gradle / pip / docker layer 这类堆出来的几 GB，要能被识别成"构建缓存，可清理"。
- **名实校验**：一个叫 `cache` 的目录里若塞了个 5GB 视频，要提醒我"名不副实，别闭眼删"。
- **认领神秘大文件**：一个文件名乱码、3GB 的 `.mp4`，希望工具抽几帧告诉我"看起来像某录屏/某电影"。
- **安全清理**：看完解释后，我用编号勾选若干条，确认后删除（进回收站，可反悔）。

## 4. 功能清单

| # | 功能 | 说明 |
|---|------|------|
| F1 | 并行全盘/指定路径扫描 | 多核遍历，输出节点树与大小聚合 |
| F2 | NTFS 精确计量 | 硬链接去重（WinSxS 不虚高）、重解析点不跟随、长路径/权限容错 |
| F3 | 递归切割成"条目" | 命中已知目录类型即打包成一个条目并停止细分；未知区域以文件树呈现 |
| F4 | 规则分类（已知目录知识库） | 给条目贴：用途、清理风险、预期内容签名 |
| F5 | 文本 LLM 兜底 | ①给未知大目录出"用途摘要"②对已知目录做"名实体检" |
| F6 | 按需逐文件分析 | 用户下钻某目录时，才对其中文件逐个让 LLM 总结用途 |
| F7 | 视频内容猜测（延后） | 文件名无意义的大视频 → ffmpeg 抽帧 → 视觉模型猜内容 |
| F8 | 交互式选择 | CLI：键入编号勾选；GUI（后续）：复选框 |
| F9 | 安全删除 | 默认移入回收站；删除前二次确认与体量汇总 |
| F10 | 扫描快照缓存 | 扫描结果落盘，重复分析/增强无需重新扫盘 |

## 5. 条目模型（用户视角）

清单里每个"条目"对用户呈现如下信息：

```
[12] 2.1 GB  📁 ~\AppData\Local\npm-cache        风险:✅可清理   来源:规则
            用途: Node.js 包缓存（删后首次安装会变慢，不影响项目）
            体检: 内容与预期一致 ✓   文件数: 318,402

[13] 4.8 GB  🎬 ~\Downloads\VID_20240118_x9f3.mp4  风险:⚠️需确认   来源:视觉
            用途: 看起来是一段户外徒步录像（抽帧推测，非确证）

[14] 6.0 GB  📁 ~\SomeUnknownApp\data            风险:❓未知     来源:LLM摘要
            用途: 疑似某应用的本地数据库与日志（下钻可逐文件细看）
```

字段：`大小 / 类型(文件·目录·媒体) / 路径 / 风险等级 / 来源(规则·LLM·视觉) / 用途说明 / 体检结果 / 文件数 / 置信度`。

## 6. 风险等级定义

| 等级 | 含义 | 由谁判定 |
|------|------|---------|
| ✅ 可清理 | 缓存/临时/可重建，删除无实质损失 | **规则（确定性）** |
| ⚠️ 需确认 | 可能有用，删前需人确认（下载、媒体、名实不符） | 规则 + 体检 |
| ⛔ 系统关键 | 系统/应用核心，**强烈不建议删** | 规则 |
| ❓ 未知 | 规则未覆盖，LLM 仅给猜测 | LLM（仅参考） |

> 规则永远优先；LLM 不得把任何条目标记为"✅可清理"，它最多给到"❓未知 + 猜测"。

## 7. 交互流程（v1 = CLI）

1. 运行 → 选择扫描盘符/路径。
2. 秒级出现"大小地图 + 规则标签"初版清单（按大小排序）。
3. 后台文本 LLM 持续把未知条目的用途/体检结果**流式刷新**进清单。
4. 用户可：`list` 看清单、`open N` 下钻目录（触发按需逐文件分析）、`why N` 看详细解释。
5. 用户键入要删除的编号（如 `select 12 14 19`）。
6. 工具汇总将释放的体积 + 风险分布，要求**二次确认**。
7. 确认后移入回收站（默认）；输出删除报告。

GUI（复选框版）为后续里程碑，复用同一分析内核，仅替换呈现/选择层。

## 8. 范围与里程碑（YAGNI）

| 里程碑 | 内容 | 是否 v1 |
|--------|------|---------|
| **M1** | 并行扫描 + NTFS 计量 + 规则切割/分类 + CLI 清单与编号删除 + 快照缓存 | ✅ v1 |
| **M2** | 文本 LLM：未知目录摘要 + 已知目录体检 + 按需逐文件 | ✅ v1 |
| **M3** | 视频抽帧 + 视觉模型猜内容（延后队列） | v1.5 |
| **M4** | GUI（复选框）+ treemap 可视化 | 后续 |

**明确不做（v1）**：直接读 NTFS MFT（先用并行遍历）、跨平台、云端模型、自动删除/定时清理。

## 9. 成功标准

- 在一块装了开发环境的真实 C 盘上，**能正确识别出前 10 大膨胀来源**，且 WinSxS 等硬链接目录大小**不虚高**。
- 清单中"可清理/需确认/系统关键"的判定**与人工判断一致**（规则覆盖部分）。
- 未知大目录能拿到一句**像样的用途摘要**；乱名大视频能拿到**方向正确的内容猜测**。
- 全流程**零误删**：没有用户确认，绝不删除任何东西。
